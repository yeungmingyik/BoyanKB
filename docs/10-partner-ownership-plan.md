# 合作伙伴所有权交接与权限调整方案

日期：2026-10-10。状态：待用户确认，尚未执行账号、成员、权限或资源归属变更。

用户正在进一步评估邀请式使用与内部员工内容建设权限，参见 [工作空间与角色方案](11-workspace-role-options.md)。本方案仍未执行；邀请式使用本身不要求交接所有权，是否保留“刘伟健不得进入伙伴空间”的额外约束需在实施前确定。

目标：刘伟健日常账号只能进入博研总部，不能切换或直接访问合作伙伴空间；卡卡继续使用星辰教育的三位智能体、九项业务技能、文档生成与员工邀请。采用独立运维账号承接管理权限，保留现有空间、资料和业务记录。

## 建议的角色安排

| 账号 | 总部 | 星辰教育 | 平台管理 | 业务能力 |
| --- | --- | --- | --- | --- |
| 刘伟健 | 保留 Owner | 移除成员关系 | 撤销 SystemAdmin，保持全空间访问关闭 | 总部资料、智能体及日常管理继续使用；不能进入伙伴空间 |
| 新建“博研平台运维” | Owner | Owner | 接任 SystemAdmin，全空间访问保持关闭 | 开通、升级、修复与权限维护；仅使用已明确授权的工作空间 |
| 卡卡 | 无成员关系 | 保持 Viewer＋指定团队负责人 | 无 | 问答、技能、本人文件及邀请只读员工 |
| 卡卡邀请的员工 | 无成员关系 | Viewer | 无 | 问答、技能、本人文件；不能继续邀请或管理授权 |

运维账号使用独立邮箱、独立密码，仅交由指定维护人员保管；不在日常浏览器中自动登录。邮箱在执行前由用户指定，密码仅在本机受保护的凭据文件中填写。邀请制、自助创建空间关闭、通用脚本沙箱关闭保持现状。

刘伟健保留总部 Owner，仍可以管理总部资料及总部对外共享关系；本方案不表示其与伙伴的所有业务关系都消失。限制对象是刘伟健的应用账号，不承诺隔离掌握运维账号、宿主机或数据库凭据的人。

`internal/teaminvitation/authorization.go` 明确要求 active Viewer、预设状态 ready、共享企业知识库模式，以及 `team_manager_user_id` 匹配本人。因此保证卡卡能力的关键是保留这些条件，不是提升他的通用角色。

`internal/handler/system.go` 的平台密钥管理和账号密码重设属于 SystemAdmin 能力。公网网关当前屏蔽这些入口，但权限分离必须在应用层完成，不能只依赖网关返回 404。

## 已核对的现状

本轮仅使用源码和只读数据库事务核查，没有读取真实密钥、登录账号或调用写接口。

- 刘伟健是总部与星辰教育的 active Owner，拥有 SystemAdmin；全空间访问标志为 false。卡卡仅为星辰教育的 active Viewer，并被绑定为团队负责人。
- 总部、星辰教育各有一条 ready 的预设开通记录，各绑定三位智能体。两条记录的所有者和六个智能体的创建者都是刘伟健；没有正在持有的开通租约。
- 星辰教育对应一个由总部持有的共享组织，组织所有者也是刘伟健。
- 平台和星辰教育在 `tenant_api_keys` 表中均没有未撤销密钥。这个结果不等于所有历史凭据都已失效；执行前仍需盘点其他认证入口及审计记录，不读取或打印密钥内容。
- 星辰教育没有尚未过期的待处理邀请，有一份已发布的文档任务。这些都是检查时的快照，执行时必须重新核对。

执行前还需确认运行环境强制开启 RBAC，不能处于仅记录但放行的模式；三个业务账号的全空间访问均为 false。密钥认证源码只查询 `tenant_api_keys`，没有旧 `tenants.api_key` 回退。仍须只读确认迁移 `000065` 已应用、旧列不存在、自动创建空间密钥关闭；满足这些条件且相关新表记录为空时，不凭空创建或轮换不存在的旧密钥。恢复旧备份后重新检查。

前一轮本机合作伙伴只读验收 26 项通过；公网只读验收在通过身份、技能、智能体、共享源及负责人检查后遇到连接失败，未完成整套验收。两者都是交接前基线，不能作为交接成功证明。证据见 [身份复核记录](09-login-layout.md#截图身份复核)。

## 执行顺序

1. **准备可审阅清单和回滚材料。** 编写默认只生成计划的受限交接脚本，核对确切对象、当前值、修订号、Owner 数量、现存管理员、认证策略及凭据元数据。保存加密备份与交接前快照；先在隔离恢复环境演练。保留旧镜像，运行配置中不暴露数据库或管理接口。
2. **建立并验证接任者。** 通过现有账号和成员 API 创建或核对运维账号，授予总部、星辰 Owner 与 SystemAdmin；保持 `can_access_all_tenants=false`。必须先验证新账号独立登录、总部及星辰权限和平台管理能力，才能撤旧权限。不能撤销最后一个系统管理员或最后一个空间 Owner。
3. **成组交接预设资源。** 在短维护窗口内等待现有生成任务和开通任务结束，阻止并发开通；一个数据库事务锁定清单内记录，按交接前值和修订号比较，更新两条开通记录、六位受管 Agent 及一个组织的所有者关联，保存前后值和审计。任一不一致均整组回滚。不得混用多个独立更新暴露不一致的中间状态。
4. **先验业务，再撤旧权限。** 确认新归属下两套预设 ready、技能读取和共享知识库访问正常，随后由新运维账号撤销刘的 SystemAdmin，并通过现有成员 API 移除刘的星辰成员关系。回读确认刘只有总部成员资格、全空间访问关闭，最后空间偏好不再指向星辰。
5. **使旧访问失效。** 成员移除流程会尝试撤销刘的全部登录令牌；必须验证实际完成，包括旧访问令牌和刷新令牌失效，不能只接受接口成功。刘需要重新登录一次，卡卡的登录令牌不因该操作被撤销。盘点并处理可继续进入伙伴空间的旧密钥及邀请，不能假设它们随成员撤除自动失效。
6. **切换维护身份并防止重新关联。** 后续开通、升级和平台配置使用独立运维凭据；新增伙伴由该账号成为 Owner。刘再次调用开通接口应被拒绝。复用原业务键重跑必须保持资源 ID 不变，不新建另一套空间或技能。飞书 helper 只需总部身份，不能为了方便把所有现有自动化凭据统一替换成运维账号；逐一核对用途。
7. **执行双向验收后结束维护。** 完成下表检查，保存脱敏报告和截图；未通过时维持维护状态并执行预先审核的回滚分支，不把半完成状态交给伙伴使用。

最小实现优先使用现有 API 加一个本机受限交接脚本。当前没有覆盖上述全部关联的统一交接 API，事务脚本只更新审核清单中的字段，不取消服务端所有者校验，不改上游 RBAC 规则。本轮尚未编写或运行该脚本。

账号创建、API 授权、数据库事务和令牌撤销不能宣称属于同一个原子事务。执行报告必须按阶段记录，支持已完成状态的幂等识别、漂移停止及中断恢复；已经处于预期归属时验证后跳过，不重复创建账号、成员或资源。

| 新员工 | 问答、技能与文件，团队管理、跨空间及他人私有资源访问 | 业务功能可用；不能再次邀请、提升角色、进入总部或读取卡卡的私有聊天/文件 |
| 运维账号 | 以原清单分别重跑总部和伙伴开通 | 两条记录保持 ready，空间、Agent、技能、共享资源 ID 和配置摘要不变；刘不会被重新加入 |
| 共享与飞书 | 比较交接前后知识库、文档、数据源和共享配置 | 单一企业知识库、19 篇资料与权限范围保持，不删除用户要求保留的探针文档 |

真实邀请验收使用用户控制的员工邮箱，不向未知第三方发送邮件；此前的模拟伙伴邮箱不能据此被视为已核验真实归属。邀请验收需要另行确认受控员工身份，密码由其本人设置，邀请链接和密码不得进入公开报告。

需要人工验证：以三个独立浏览器身份检查刘、卡卡和新员工的实际菜单与切换结果；新员工亲自接受邀请并设置密码；用 Office 打开生成的 Word，核对品牌、正文及引用；确认运维凭据的保管人。自动检查只证明相应请求与结构校验结果，不能代替这些检查。

## 回滚

- 新账号准备失败时保留刘的原权限，不继续交接；新建对象登记在报告中，不擅自删除。
- 所有者事务内失败则事务回滚；提交后业务验收失败，依据保存的前后值先验证没有并发业务改动，再执行对应所有者字段的反向事务，不恢复整库覆盖新聊天或文件。
- 已移除刘成员后，优先由运维账号完成修复，保持已确认的权限边界。若必须临时恢复刘的伙伴 Owner 或 SystemAdmin，这会重新打开用户要求关闭的访问范围，必须由用户另行确认。
- 已撤销的令牌不恢复，相关账号重新登录。保留运维账号直到验收和回滚窗口结束，不因清理造成空间无 Owner 或平台无管理员。
