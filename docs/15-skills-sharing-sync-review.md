## 1. 业务技能是否需要独立页面

“业务技能”是 BoyanKB 定制入口，独立页面不是技能执行的必要条件。它面向普通成员展示五个业务场景、四种文件格式、实际开通状态及中文说明，并提供“使用落地方案官”按钮。点击按钮只进入聊天并选中 Agent，不会自动发消息。

“技能管理”沿用原生技能目录及安装管理方式，当前定制版本支持管理员上传包含 `SKILL.md` 的 ZIP 包，或导入来源地址；没有在线编写 Skill 的文本编辑器。当前部署关闭通用代码沙箱，保存一个技能包不表示它已获得执行能力。

| 项目 | 业务技能 | 技能管理 |
| --- | --- | --- |
| 当前主要用途 | 查看和使用已授权业务能力 | 保存、查看及管理技能包 |
| 当前界面权限 | 当前工作空间 Viewer 及以上 | Admin、Owner |
| 九项业务预设 | 显示中文说明和实际开通状态 | 相同技能包已经登记在目录中，并非另一份独立业务内容 |
| 执行路径 | 受管 Agent、固定版本指南、文档生成服务 | 通用 Skill 通常需要安装到沙箱；本部署未启用该执行路径 |
| 修改业务预设 | 通过版本化预设维护 | 不能直接覆盖或删除已受管的九项技能包 |

九项技能的开通脚本先调用 `/api/v1/skills/catalog` 登记技能包，再登记受限技能的版本、摘要及启用状态。文档生成通过 `boyan_document` 工具读取指南、校验资料引用、提交大纲、等待用户确认、生成及审校文件。删除展示页面不会直接删除这些后端能力，但会影响普通成员发现和使用它们。

### 建议方案，尚未实施

工具箱可只保留一个“技能管理”入口，页面内部按权限提供：

- 所有成员可见的“可用技能”：保留九项业务技能的中文说明、真实授权状态和使用按钮。
- Admin、Owner 可见的“技能包管理”：保留上传、导入、查看文件和允许范围内的删除操作。

最小实现是复用现有业务技能组件及原生技能管理组件，合并导航和展示层，将旧业务技能链接重定向到统一入口。无需迁移技能数据，也无需开启通用代码沙箱。应保留业务预设摘要校验、受管包保护、资料范围、用户确认和审校流程。

不能仅将整个原生管理页面开放给 Viewer：该页面目前包含管理操作，且后端包文件读取和写入仍要求 Admin。导航可见性与后端授权必须分别保留。也不能仅删除业务入口而不补齐只读展示，否则普通合作伙伴失去现有入口。

实现依据：

- `frontend/src/config/toolbox.ts`：两个工具箱入口及业务技能 Viewer 可见规则。
- `frontend/src/config/settingsAccess.ts`：技能管理界面要求 Admin。
- `frontend/src/views/toolbox/BusinessSkills.vue`：业务目录、说明及选中 Agent。
- `frontend/src/views/settings/SkillSettings.vue`：包管理、九项中文显示及业务入口链接。
- `scripts/onboard-partner.py`：技能包登记及受限预设安装。
- `internal/router/routes_agent.go`：技能目录读取与管理操作的后端权限。
- `internal/businessworkflow/skills_catalog.go`、`internal/boyanskills/provider.go`：成员资格、开通记录、固定指南和摘要检查。
- `internal/application/service/tenant_skill_catalog.go`：受管预设禁止覆盖和删除。
- `branding/brand.json`、`deployment/tencent/Caddyfile.ip-https`：当前通用技能执行开关及网关限制。

整合后需验证：管理员与 Viewer 分别查看页面；切换空间无旧状态残留；九项技能不重复展示；Viewer 直接请求管理 API 仍被拒绝；已有受管 Agent 及文件任务不受影响。这些是后续改动的检查项，本次未实施整合，也未声称检查已通过。

目前不是实时同步，也没有每隔几分钟自动刷新。最近同步时间是迁移后保留的数据源记录，不能据此认为云服务器在该时刻执行过同步。

### 触发与处理过程

1. 管理员在企业知识库的“设置 → 数据源”中，找到飞书数据源，通过操作菜单选择“立即同步”。当前暂停状态仍允许人工触发。
2. 后端将任务加入同步队列；应用使用飞书应用身份 `tenant_access_token`，枚举配置的目标空间中当前应用可见的目录。
3. 首次无游标时遍历并导入可见文档；以后仍检查目录，依据文档内容编辑时间与游标比较，跳过未变化内容。没有内容编辑时间时回退使用节点编辑时间。这是轮询比对机制，不是飞书事件推送。
4. 新增或修改项导出并进入本地知识处理流程，按当前知识库配置解析、分块及建立索引。`overwrite` 意味着本地导入内容以源文档为准，不适合在本地副本上维护独立修改。
5. 在“同步日志”查看总量、新增、更新、失败情况，再检查文档解析状态。触发成功只表示任务已入队，不代表十九篇都已更新完成。

`paused` 与空定时表达式不会取消已经入队的任务及其重试；同步任务配置最多五次重试。因此它们不能作为“绝不会再请求飞书”的保证。本次未触发新任务，也未重新检查全部队列的实时状态。

删除同步当前关闭：即使飞书原文被删除，本地副本仍保留，并可能继续出现在检索结果中。此为当前保留策略，不是双向同步；连接器不会删除飞书原文。若以后启用删除同步，需要先区分真实删除与应用失去文档访问权限，避免将权限收缩误判为删除。

### 操作入口与未验证事项

云端应使用管理员网页的数据源手动同步入口。旧 `scripts/feishu-space-sync.py` 为本机环境设计，包含回环地址、容器及模型配置检查，不能直接替换为公网 HTTPS 地址后当作云端同步脚本使用。该脚本的策略校验也不能代替后台所有同步入口的权限控制。

本次确认了云端数据库配置和十九篇解析完成记录，**未实时比对飞书当前目录**，不能保证今天飞书端仍恰好十九篇，也不能保证近期改动已入库。

后续验证方法：

- 管理员以有权身份检查飞书目标空间的实际节点列表，与云端本数据源的来源 ID 集合核对；仅比较文档数量不足以证明内容一致。
- 触发一次手动同步，等待同步日志结束及全部文档解析完成，再核对来源更新时间、内容摘要和真实检索结果。
- 新建、修改、删除的端到端行为：**未在本次云部署中验证**。应使用专用文档逐项检查，删除项按当前“本地保留”策略验证；不要删除业务资料来测试。
- 应用对其他空间是否被拒绝：**未在本次核查中验证**。固定目标空间限定此数据源的同步范围，但不能证明飞书应用身份在所有其他位置均无权限。
