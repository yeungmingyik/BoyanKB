# BoyanKB 版本路线

当前规划版本：`0.1.0-alpha.1`。除基线与规划外，下列产品功能均未实现；验收结果以 [验收清单](acceptance.md) 为准。

| 版本 | 交付范围 | 完成门槛 |

| 0.1.0-alpha.3 | `whole_space` 完整发现；同步台账；全量与增量同步；资料目录与系统内原文预览；重试与删除处理 | AC-08 至 AC-16、AC-18、AC-34；完整盘点嵌入对象和实际格式缺口 |

## 2. 首期实施顺序

1. 使用原生 `create-user` 建号；关闭自主注册和社交注册，保留邮箱登录；需要定向邀请时配置 SMTP 并使用 `invite-user`。管理员持有知识 Agent，通过原生分享界面逐用户授予 `VIEW`；禁用普通用户创建 Agent、分享和上传。
2. 建立可重复启动的本地环境，相关入口统一检查 Agent `VIEW` 与 `checkBan`；移除 `VIEW` 执行永久撤权，原生限时封禁用于临时停用；清理刷新会话并完成账号权限与个人会话验收。
3. 从配置入口解析整个知识空间，建立稳定资料标识、逐项同步状态及嵌入对象清单。
4. 完成文档和实际附件适配、版本发布与系统内预览，验证重试与下线行为。
5. 接入检索与问答，复用原生聊天入口，将引用接入系统内预览。
6. 在确定的目标网络开展伙伴试点，记录真实资料覆盖、使用缺陷和设备负载。
7. 完成格式覆盖、数据恢复和升级演练后发布本地正式版本。

## 3. 决策节点

| 决策 | 期限 | 默认边界 |
| --- | --- | --- |
| 原生管理能力与权限覆盖 | alpha.2 开发前 | 使用 `ADMIN`、`USER`、原生命令和原生 Agent 分享界面；核验并补齐 `VIEW` 与 `checkBan` 检查，不建设独立伙伴后台 |
| 资料格式与对象范围 | alpha.3 验收前 | 完整抽取后确认，不能依据节点均为文档推断全部内容可解析 |
| 嵌入服务与 RAG 版本 | alpha.3 开发前 | 固定版本、向量维度、数据流向与成本，验证文件入库 |
| 问答模型 | alpha.4 开发前 | 配置化服务位置与凭据，明确数据流向和成本 |
| 伙伴网络入口 | beta.1 试点前 | 开发使用 localhost；远程访问方案待定，VPN 未确认 |
| 运行规格与服务指标 | beta.1 试点前 | 基于实际 PC、模型、语料和并发规模确定，不预填未经测量的性能结果 |
| 云端部署规格 | 0.2.0 开发前 | 依据本地正式版使用规模与恢复要求确定 |

## 4. 版本管理

- BoyanKB 产品版本与 LibreChat 上游包版本分别维护。
- 使用语义化版本，预发布标识采用 `alpha`、`beta` 及递增序号。
- 产品版本、Git 标签和更新日志一一对应；标签采用 `v<产品版本>`。
- 更新日志只记录该版本实际交付的新增、变更和修复；未完成事项保留在路线中。
- 分支使用实际功能命名，例如 `feishu-sync`、`authorized-access`、`knowledge-search`，不使用 `codex/` 前缀。
- 提交信息遵循 Conventional Commits，提交身份使用仓库所有者配置，不增加工具或代理署名。
- 上游更新先核对差异与兼容性，再更新锁定提交并执行受影响范围的验收。
- 未通过版本门槛不得标记为正式发布。

## 5. 后续候选

伙伴标签、细分授权、多知识源、飞书写回、报名与付费、活动运营及申请办理不属于首期。新增需求先形成范围、数据边界和验收条件，再安排版本。
