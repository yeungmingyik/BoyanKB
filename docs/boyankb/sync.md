# 飞书同步规格

## 范围与身份

从部署配置中的 Wiki URL 解析 `space_id`，从空间根节点开始分页、递归枚举全部节点。入口可能是叶子文档，不能把入口子树作为整个空间。

知识空间中的全部资料面向已授权用户发布，不逐篇增加对伙伴的审批环节。知识内容只在飞书编辑，系统不写回、不改飞书成员和共享权限，也不把飞书凭据交给伙伴。

开发盘点可使用已有授权的 lark-cli user 身份。长期同步使用企业自建应用的只读身份，验证其完整空间可见性；若应用身份不可覆盖，使用专用集成账号的 OAuth 离线授权，持久化加密刷新凭据。不得把开发者桌面的 lark-cli 登录目录当作运行时依赖。

按照实际 API 申请 Wiki 读取、文档读取、文件元数据读取和下载权限；嵌入对象按需增加对应只读权限。应用 scope 与源文档访问授权分别验证。凭据失效显示连接异常，不能静默更换身份或扩大权限。

应用创建、读取权限和整空间授权步骤见 [飞书应用开通](feishu-setup.md)。

## 调度

- 首次完整扫描；默认每 10 分钟轮询，每 24 小时执行一次完整对账；均可配置。
- 本地首期采用轮询，不依赖公网回调。云端可增加事件通知加速，完整对账仍保留。
- 同源单任务运行，MongoDB 原子租约控制并发，租约过期后可接管；持久化分页游标与阶段结果。
- 429、可恢复 5xx 和网络错误使用指数退避与抖动，尊重服务端重试间隔；认证错误停止相关任务并提示管理员。
- 任务不可将日志写成资料副本。日志只包含内部 ID、阶段、耗时、状态和脱敏错误。

## 同步步骤

1. 校验源身份、空间和读取权限，创建扫描 ID。
2. 分页列出空间根节点及每个目录的所有子节点，记录层级；处理循环与重复快捷方式。
3. 按对象类型提取正文、目录、表格和素材关系，计算内容摘要；递归解析允许范围内的嵌入对象。
4. 保存不可变快照，下载许可可用的素材，建立原生文件映射。
5. 写入原生检索索引，验证快照可读、索引成功及引用定位。
6. 原子切换生效版本；仅生效版本参与新检索和问答。
7. 完成全部分页后进行删除对账；记录覆盖率和失败项。

幂等键包含源标识、对象类型、对象 token、内容摘要、解析器版本和索引版本。仅改标题或移动节点更新目录元数据，不重复入库相同正文。一个内容对象可有多个空间节点。

Docx 内容块使用 `document_revision_id=-1` 读取最新版本。采集前后核对 `revision_id`，版本变化时重新采集，一致后发布快照；不为读取历史版本扩大为编辑权限。

## 状态

| 状态 | 对外行为 |
|---|---|
| discovered / pending | 管理端可见；尚未对用户发布 |
| extracting / indexing | 保留仍有效的旧快照，管理端显示更新处理中 |
| published | 当前快照可读且参与检索 |
| partial | 管理端展示已解析部分和缺失项，不切换生效版本；已有有效旧版本继续服务 |
| failed | 记录失败阶段；旧版本仍有源授权时保留并显示资料时间 |
| unsupported | 保留目录与格式状态，不伪造空白正文 |
| inaccessible | 已确认源权限失效，停止提供该资料及素材、检索和引用 |
| removed | 已确认删除或移出同步空间，资料下线 |

网络暂断与权限撤销分开处理：超时可以保留已有合法快照；明确的无权响应下线相应资料。空间级鉴权失败暂停该源对外服务，等待重新验证，不触发批量物理删除。

一次完整扫描缺项只生成待核实项。立即执行对象状态复核，或补做成功完整扫描且确认已移出范围后下线，不等待下一个日周期。任一分页失败、授权失效或扫描中断，不执行缺项删除。

下线立即从生效文件列表移除，目录、正文、素材、旧引用和新问答均不可访问。历史聊天已存文本不自动重写；重新打开历史引用显示资料已下线。暂存对象和孤立索引按保留策略清理，幂等重试。

## 格式与发布门槛

| 格式 | 处理目标 | 验收边界 |
|---|---|---|
| 飞书 Docx | 标题、段落、列表、表格、代码、图片关系 | 遍历所有分页与嵌套块，保持阅读顺序 |
| 图片 | 本地快照与预览 | 无 OCR 时仅图旁文字可检索，不宣称图中文字已识别 |
| PDF / DOCX / PPTX / 文本附件 | 下载、抽取、阅读或内嵌预览 | 对每种实际格式验证；扫描 PDF 需 OCR 后才算正文可检索 |
| 飞书 Sheets / Base | 通过独立 API 提取表格或视图快照 | 不能用 Docx 文本替代嵌入数据，不自动同步空间外整套数据源 |
| 画板、音视频、妙记 | 预览、转写或明确未支持状态 | 在实际出现后列入适配任务 |
| 外部链接 | 保留链接文字，标明外部来源 | 不自动爬取任意外部网站或私网地址 |
| 跨空间快捷方式 | 单独识别目标所属空间 | 超出源范围的目标待管理员决定是否新增源，不静默扩大同步范围 |

嵌入对象属于同步覆盖的一部分，独立记录 ID、格式、可读性和索引结果。首期发布前对实际出现的所有对象建立清单；阻塞关键业务资料阅读的缺失格式必须完成适配，不能以“18 个 Docx 节点已发现”代替完整覆盖。

## 覆盖率

分别展示：空间节点总数、去重内容对象数、嵌入对象数、已发布正文数、可读素材数、可检索对象数、未支持数、失败数、无权限数和最近完整扫描时间。

节点覆盖率以完整枚举节点数为分母；内容可用率以已发现去重内容对象数为分母；嵌入素材单独统计。未完整扫描时不显示 100% 或“全部同步”。

## 时间与保留

存储 UTC 时间，界面按用户时区显示。区分源更新时间、抽取时间、索引时间与发布时间。源文档内容更新目标为正常依赖情况下 15 分钟内可用；删除与移出由下一次完整对账识别，发现窗口为 24 小时加扫描耗时，确认后 5 分钟内完成下线。手动完整同步可加速。

首期默认保留历史快照 30 天、任务和审计 90 天，均为可配置运维值。下线资源即使尚未物理清理，也不得对用户读取。备份独立遵循部署保留策略。

## 连接配置契约

部署配置至少包含 Wiki URL、期望空间 ID、企业 Agent ID、身份模式、轮询与对账周期、并发和重试上限、素材大小限制、快照保留策略。机密包含应用密钥、OAuth 刷新凭据及模型密钥，存于 Git 忽略的本地秘密文件或云秘密管理器。

源地址和真实 token 只存本地配置；公开仓库使用空值或测试源。内容采样、盘点清单和评测资料保存在忽略目录，提交时仅使用人工构造的测试样本。
